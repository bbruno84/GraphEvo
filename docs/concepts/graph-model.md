# Graph model

GraphEvo organizes data as a set of connected objects. The main benefit is
that it describes not only objects, but also their connections and the actions
in which they participate.

## `Graph`

`Graph` represents an open store. It is the entry point for:

- creating `Entity`, `Relationship`, and `Action` objects;
- executing searches;
- saving or deleting data;
- receiving opening, persistence, and synchronization events.

```swift
var configuration = GraphStoreConfiguration()
configuration.name = "Main"
let graph = Graph(configuration: configuration)
```

When the opening result matters, use `whenReady` instead of assuming that the
graph is ready.

## `Node`

`Node` is the common base. Every node has:

- `type`: a logical type such as `"User"` or `"Note"`;
- `id`: a persistent identifier generated by the library;
- `createdDate`: the creation date;
- dynamic properties accessible with `node["key"]`;
- tags and groups.

```swift
let user = Entity("User", graph: graph)
user["name"] = "Ada"
user.add(tags: "active")
user.add(to: "authors")
```

Properties are `Any?`, so they are flexible but require care when storing
complex or non-codable values.

## `Entity`

An `Entity` represents a domain object. Its type is not a Swift class, but a
string chosen by the application. This allows multiple data types to share the
same API.

```swift
let note = Entity("Note", graph: graph)
note["title"] = "GraphEvo"
note["isArchived"] = false
```

An entity can read actions and relationships for which it is subject or object:
`actions`, `actionsWhenSubject`, `actionsWhenObject`, `relationships`,
`relationshipsWhenSubject`, and `relationshipsWhenObject`.

## `Relationship`

A relationship is a directed, typed connection:

```text
subject --type--> object
```

Example:

```swift
user.is(relationship: "writes").of(note)
```

Here `user` is the subject, `note` is the object, and `"writes"` is the type.
The same relationship can be built by assigning `subject` and `object` directly.

## `Action`

An action describes an event or activity. It may have multiple subjects and
objects:

```swift
let review = user.will(action: "reviews")
review.add(objects: note)
```

`subjects` and `objects` return the associated entities. `will(action:)` and
`did(action:)` are shortcuts that add the calling entity as an action subject.

## Tags and groups

Tags are labels, while groups represent membership. Both are sets and contain
no duplicates.

```swift
user.add(tags: "active", "verified")
user.remove(tags: "verified")
user.toggle(tags: "featured")

if user.has(tags: ["active", "featured"], using: .and) {
    // Both labels are present.
}
```

All mutation operations return the node and can be chained. `delete()` removes
the node from the context; call `graph.sync()` to persist the deletion.

## Practical rules

- Always create objects with the correct `Graph`.
- Use `Relationship` when the connection is an independent, typed datum.
- Use `Action` when an event involves multiple participants.
- Do not use Core Data `Managed*` classes directly.
- Explicitly save with `sync()` after a sequence of changes.
