# V01 T0 — cross-device control result

Status: observed on 2026-10-23. This completes the single-store T0 control in the
[V01 procedure](../graphevo-2-v01-procedure.md) under the conditions below.
T1–T5 have not been implemented or executed. This is not evidence of graph
separation or a decision about GraphEvo 2 topology.

  Existing personal Xcode project/plist changes were retained outside the commit.
- The build recorded the SHA256 of sorted relative Swift source paths followed
  by their bytes: `3ccd42ea2060dfc331cce634bc674fbea269cee690576f9325dd82892ed1668a`.
  Both installed apps reported that same provenance. The hash covers the app's

## Procedure and observed outcome

Run ID: `D018B7B0-882B-44D5-86FA-608676B8636D` (synthetic experiment identifier).

The writer ran on the iPhone with a fresh SQLite path and inserted three fixed
rows: A-001/alpha, A-002/beta, and B-001/gamma, with logical graph markers A/B.
These markers belong to one control store; they do not partition cloud storage.
The writer observation window was 120 seconds. It saved locally and reported
successful native setup/import/export events, with no recorded stage errors.
Its final report was retained at 19:38:10 UTC.

The first iPad launch was rejected because the device was locked; no reader
stage ran in that attempt. After the user unlocked it, the same signed binary
ran as reader with the same run ID and a new, independently generated SQLite
path. The reader never called the insertion operation. It recovered all three
expected rows with the exact values, observed a successful native import, and
retained its completed report at 19:39:18 UTC. No stage errors were recorded.

Independent comparison of the final reports confirmed:

- identical expected and recovered rows, with no missing or duplicate fixture;
- different local store identifiers, process identifiers, and stage identifiers;
- matching record-name and zone-name components for each fixture item within
  the externally verified same-account/container/environment scope;
- the observed zone name `com.apple.coredata.cloudkit.zone` for these rows;
- no native events dropped by the report's bounded event capture.

The final reader state establishes observed fixture recovery on an independent
physical peer, beyond the writer's local save or export event alone. It does
not establish universal mirroring reliability or bounded synchronization timing.

The attached console commands then exited with status 1 due to that intentional
termination; the completed JSON reports, not those console exit codes, establish
the stage outcomes. Local fixture files and reports were retained. No remote wipe,
zone purge, app removal, or deletion of the normal demo's stores was performed.
Synthetic server fixtures remain and are scoped by the recorded run ID.

The demo's 16 local XCTest cases passed separately. They validate harness and
integration behavior, not the cross-device outcome recorded here. The hardware
run is not a substitute for multi-scene UI acceptance or broader OS coverage.
